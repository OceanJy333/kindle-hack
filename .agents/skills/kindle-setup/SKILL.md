# Kindle Setup

把本仓库交给你的用户，通常希望你执行设置。先读仓库 [README](../../../README.md)、[设置指南](../../../docs/setup.md)；构建时按 [BUILD.md](../../../BUILD.md) 找实际命令和外部输入。仓库根目录是本 Skill 向上三级。

## 先识别设备

从用户已有描述取得准确型号、固件、是否越狱、电脑系统、目标功能和连接方式。缺少影响下一步的信息时集中询问。连接后读取 `uname -a`、`uname -m`、挂载、输入设备和显示参数，补全判断。

本项目以 Kindle Voyage、ARMv7、原厂 5.13.6 为起点。Ocean 的设备后来运行自编译 `3.0.35-ocean-voyage` 内核。其他型号需要检查处理器 ABI、分辨率、framebuffer / EPDC ioctl、输入设备与运行库后适配。

- **尚未越狱**：先打开 [KindleModding 入门](https://kindlemodding.org/jailbreaking/)和[当前越狱向导](https://kindlemodding.org/jailbreak-wizard.html)，按设备型号、固件与注册状态选择路线，协助准备文件并指导用户完成设备上的操作。WinterBreak 的当前指南明确不支持 `5.18.1` 及之后版本。每次以原项目当前指南为准。
- **原厂系统已越狱**：确认能运行 root 命令，再配置该设备支持的 SSH 和启动入口。使用本机生成的密钥与现场核对的主机指纹。
- **已运行 Voyage 独立系统**：确认 `/opt/ocean`、`/tmp/weread-native`、服务和挂载；沿现有系统布局更新应用。

越狱使设备能运行外部程序；安装应用通常可以保留原厂系统。用户要求读书、游戏或看板时，先完成所选应用。换系统、写引导器、刷内核和分区是单独目标，须有对应明确请求，并先确定该设备的恢复入口、备份与面板校准数据。

## 构建与配置

1. 看 [BUILD.md](../../../BUILD.md) 和目标脚本。列出真正缺少的工具、原包或用户资源，再构建所选功能。
2. 微信读书需要用户自己取得官方包，使用仓库提取和补丁工具生成适配资源。游戏 WAD、ROM、BIOS 由用户自备。固件、面板波形和校准数据来自该用户自己的设备或对应来源。
3. 依脚本支持的参数配置设备地址、端口、SSH 密钥和电脑地址。用户未启用 SSH 时，按其现有越狱工具准备对应入口。先查脚本实际读写路径，使用当前系统的挂载和程序位置。
4. 上传并手动启动构建产物，验证后配置启动入口。先核对现有程序及用户数据的位置，保留账号、离线书库、存档和已有公钥。
5. 通过重启后启动检查，才将结果记为持久安装。仅在 `/tmp` 生效的覆盖记为临时运行。

普通的依赖安装、本地构建、传输、应用配置与启动在用户要求的设置范围内继续完成。扫码、触摸和实体操作交给设备旁的用户；其余部分继续推进。

## 关键差异

- 原厂系统旧运行包在 `/mnt/us/native-runtime.ext2`，挂载入口 `/tmp/weread-native`；独立系统应用在 `/opt/ocean`。以设备和当前启动脚本为准。
- 两种游戏共用 `games/display-worker.c` 的 A2 / GC16 更新。供帧率不等于墨水屏的实际帧率。
- 微信读书是原生 Qt 适配。实际账户自行扫码，阅读权限取决于该账户。云端进度、段落评论和离线缓存分别验证。
- `weread/official/port/main.cpp` 加载运行目录的 `ca-certificates.crt`。遇到 HTTPS 错误，检查设备时钟、CA 文件与实际运行版本，保留证书验证。
- `system/shoot-overlay.sh` 用于临时拍摄覆盖，重启消失。CA 加载修复需编译进实际使用的运行包。

## 交付

按用户选的功能实际测试：阅读器扫码、开书、翻页、评论、双向进度和离线；游戏操作与退出；桌面亮度、休眠和唤醒。需要设备配合的部分请用户操作并回读结果。

最后用简短清单说明装到了哪里、怎么启动、已验证什么、还有什么未验证。构建通过、模拟器运行、真机运行和持久安装分别陈述。凭据、账号、书籍缓存与设备私有数据留在用户本地。
